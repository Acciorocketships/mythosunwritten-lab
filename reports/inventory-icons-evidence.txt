Evidence for W-inventory-icons -- an inventory row that shows the item, not a
generic mark. Implementer run, cycle 3633. Every block is a command run from
the project root.

==============================================================================
1. The decision, and its cost as a number
==============================================================================
Drawn sixteen-pixel faces, one per gear tag -- not the item's own model
rendered small to a texture. The reason is the seam the panel has been held to
since it existed: a drawn face is three of the pack's own colours on the pack's
own 16-pixel cell, so the two numbers that police the seam (off-palette pixels,
off-grid colour changes) stay at zero by construction. A lit, shaded mesh
rendered to a texture is off-palette by construction, and it would need a live
viewport, which the project's "a headless run loads no interface" claim forbids.

  icons drawn                8  (dagger spear bow staff flail buckler
                                 draught bundle)
  gear tags covered         13  (AssetTags.in_category(AssetTags.GEAR))
  tags reusing sheet art     5  (gear_blade -> hand's sword; gear_boots,
                                 gear_leggings, gear_chestplate, gear_helmet
                                 -> the four armour-slot icons)
  tag with no row           ->  the tied parcel, PixelIcons.GEAR_FALLBACK,
                                 the same answer render/ground_items.gd gives
                                 an unnamed item on the ground

==============================================================================
2. How many shipped items take the fallback
==============================================================================
7 of 49. Pinned as constants in tests/test_ground_items.gd
(SHIPPED_FALLBACKS := 7, SHIPPED_ITEMS := 49) and counted by
TestGroundItems.shipped_tally(), which walks every scenario the shell can set
out, reads every actor's inventory and every ground object, and resolves each
item with ItemModel.of -- the identical call the panel makes through
Inventory.item_of, so it is the same count.
